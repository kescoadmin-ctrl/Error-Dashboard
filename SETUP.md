# Supabase Setup Guide for KESCO Dashboard

This guide walks you through setting up a Supabase project for the KESCO Error Dashboard.

## Prerequisites

- Google or GitHub account (for Supabase login)
- Node.js 16+
- A code editor (VS Code recommended)

## Step-by-Step Setup

### 1. Create Supabase Project

1. Go to [Supabase Dashboard](https://app.supabase.com)
2. Click **"New project"**
3. Enter project details:
   - **Name**: `kesco-dashboard`
   - **Database Password**: Create a strong password (you'll need this)
   - **Region**: Choose the closest region to your users
   - **Pricing Plan**: Free tier is sufficient
4. Click **"Create new project"** and wait for initialization (2-3 minutes)

### 2. Create Database Tables

Once your project is ready, go to the **SQL Editor** and create the following tables:

#### Users Table

```sql
create table public.users (
  id uuid primary key references auth.users(id) on delete cascade,
  email text unique not null,
  role text not null check (role in ('administrator', 'coordinator')),
  settings jsonb default '{"topN": 10}'::jsonb,
  created_at timestamp with time zone default timezone('utc'::text, now()) not null,
  updated_at timestamp with time zone default timezone('utc'::text, now())
);

alter table public.users enable row level security;

-- Allow users to read/update their own data
create policy "Users can view their own data" on public.users
  for select using (auth.uid() = id);

create policy "Users can update their own data" on public.users
  for update using (auth.uid() = id);
```

#### Snapshots Table

```sql
create table public.snapshots (
  id bigint primary key generated by default as identity,
  user_id uuid not null references public.users(id) on delete cascade,
  date_str text not null,
  filename text,
  timestamp text,
  selected_columns text[],
  has_source boolean,
  flagged jsonb[] default '{}'::jsonb[],
  record_count integer default 0,
  flag_count integer default 0,
  created_at timestamp with time zone default timezone('utc'::text, now()),
  updated_at timestamp with time zone default timezone('utc'::text, now()),
  unique(user_id, date_str)
);

alter table public.snapshots enable row level security;

-- Allow users to see only their own snapshots
create policy "Users can view their own snapshots" on public.snapshots
  for select using (auth.uid() = user_id);

create policy "Coordinators can create snapshots" on public.snapshots
  for insert 
  with check (auth.uid() = user_id);

create policy "Coordinators can update their snapshots" on public.snapshots
  for update using (auth.uid() = user_id);

create policy "Coordinators can delete their snapshots" on public.snapshots
  for delete using (auth.uid() = user_id);
```

### 3. Setup Storage Bucket

1. In Supabase dashboard, go to **Storage**
2. Click **"Create a new bucket"**
3. Name it: `snapshots`
4. **Uncheck** "Public bucket" (for security)
5. Click **"Create bucket"**

#### Configure Storage Policies

Click on the **snapshots** bucket, then go to **Policies**:

```sql
-- Allow authenticated users to upload to their own path
create policy "Users can upload their own files" on storage.objects
  for insert 
  with check (bucket_id = 'snapshots' and auth.role() = 'authenticated');

-- Allow users to read their own files
create policy "Users can read their own files" on storage.objects
  for select using (bucket_id = 'snapshots' and auth.role() = 'authenticated');

-- Allow users to delete their own files
create policy "Users can delete their own files" on storage.objects
  for delete using (bucket_id = 'snapshots' and auth.role() = 'authenticated');
```

### 4. Enable Email/Password Authentication

1. In Supabase dashboard, go to **Authentication** → **Providers**
2. Find **Email** provider
3. Make sure it's **Enabled**
4. Optionally disable "Confirm email" if you want instant access
5. Click **"Save"**

### 5. Create First Users

#### Administrator User

1. Go to **Authentication** → **Users**
2. Click **"Invite"**
3. Enter:
   - Email: `admin@yourdomain.com`
   - Check "Send invite email"
4. User receives email with confirmation link
5. Once confirmed, go to **SQL Editor** and add user profile:

```sql
insert into public.users (id, email, role)
select id, email, 'administrator'
from auth.users
where email = 'admin@yourdomain.com';
```

#### Coordinator User

Repeat for coordinator:

```sql
insert into public.users (id, email, role)
select id, email, 'coordinator'
from auth.users
where email = 'coordinator@yourdomain.com';
```

### 6. Get Your API Keys

1. Go to **Settings** → **API** in Supabase dashboard
2. Find the **Project URL** (under "API")
3. Find the **anon public** key (under "Your API keys")
4. Copy both values

### 7. Configure Environment Variables

1. In your project root, create or edit `.env`:
   ```
   VITE_SUPABASE_URL=your_project_url_here
   VITE_SUPABASE_ANON_KEY=your_anon_key_here
   ```

   Replace with values from step 6.

2. Save the file. **Do NOT commit `.env` to version control**

### 8. Install Dependencies and Test

```bash
npm install
npm run dev
```

Visit `http://localhost:5173` and test:
1. Click "Administrator" → Login with admin@yourdomain.com
2. Click "Coordinator" → Login with coordinator@yourdomain.com
3. Try uploading a test file (as Coordinator)

## Database Schema

After setup, your Supabase database should have:

### users table
```
id (UUID)          → Links to Supabase Auth
email (TEXT)       → User's email
role (TEXT)        → 'administrator' or 'coordinator'
settings (JSONB)   → User settings (topN, etc.)
created_at         → Account creation timestamp
updated_at         → Last update timestamp
```

### snapshots table
```
id (BIGINT)              → Primary key
user_id (UUID)           → Owner of snapshot
date_str (TEXT)          → Date identifier (YYYY-MM-DD)
filename (TEXT)          → Original file name
timestamp (TEXT)         → Upload timestamp
selected_columns (TEXT[])→ Selected columns from file
has_source (BOOLEAN)     → Whether SOURCE column exists
flagged (JSONB[])        → Array of flagged records
record_count (INTEGER)   → Number of records
flag_count (INTEGER)     → Number of flagged items
created_at               → Creation timestamp
updated_at               → Last modification timestamp
```

### Storage
```
gs://project.appspot.com/
  {user_id}/
    snapshots/
      {date_str}/
        records.json  (contains all records + flagged rows)
```

## Row Level Security (RLS)

All tables have RLS enabled with policies that ensure:
- Users can only see their own data
- Coordinators can manage their own snapshots
- Administrators can view but not modify
- Data is protected at the database level

## Troubleshooting

### "Relation does not exist" error
- Run all SQL commands in the **SQL Editor**
- Make sure you're running them in the correct database
- Tables must be created in the `public` schema

### "Permission denied" when accessing data
- Check RLS policies are created correctly
- Verify user is authenticated
- Ensure user.id matches the owner_id in policies

### Login fails with "Invalid login credentials"
- Verify user exists in `auth.users` table
- Check user profile exists in `public.users` table
- Ensure role is exactly 'administrator' or 'coordinator' (case-sensitive)

### Can't upload files to storage
- Verify storage bucket exists and is named `snapshots`
- Check storage policies are created
- Ensure authenticated user has upload permissions

### Can't find API keys
1. Go to Supabase Dashboard
2. Select your project
3. Go to **Settings** → **API**
4. Copy "Project URL" and "anon public" key
5. Paste into `.env`

## Deploying to Production

### Deploy to Vercel, Netlify, or Similar

1. Build the app:
   ```bash
   npm run build
   ```

2. Set environment variables in your hosting platform:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`

3. Deploy the `dist` folder

### Production Checklist

- [ ] RLS policies are strict (deny by default)
- [ ] Storage bucket is private (not public)
- [ ] Email authentication requires confirmation
- [ ] Backups are enabled in Supabase
- [ ] Monitoring/logging is configured
- [ ] CORS is configured for your domain
- [ ] Environment variables are set in production
